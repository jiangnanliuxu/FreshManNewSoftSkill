# Software Dev Guide 使用说明

`software-dev-guide` 是一个面向软件开发全流程的 Codex Skill。它用 Harness 方式控制 LLM 的执行流程，帮助用户从需求整理、产品设计、技术方案、模块开发、测试验证，到上线准备和最终交付文档逐步推进。

## 适用场景

- 从 0 开始做网站、App、小程序、后台系统、数据看板、自动化工具。
- 课程设计、作业、毕业设计、个人项目。
- 已有项目中断后继续开发。
- 开发中新增需求、撤销需求、修复问题。
- 需要生成测试报告、上线检查清单、最终交付说明。
- 想在产品设计阶段选择 Codex 原生 UI 或 Stitch 增强 UI。

## 推荐使用方式

在 Codex 中可以这样说：

```text
使用 software-dev-guide，带我从 0 开始做一个学生管理系统。
```

继续已有项目：

```text
使用 software-dev-guide，继续开发这个项目，项目路径是 /path/to/project。
```

新增需求：

```text
使用 software-dev-guide，我要在当前项目里新增管理员登录功能。
```

生成最终交付说明：

```text
使用 software-dev-guide，帮我整理这个项目的最终交付文档。
```

## 三种复杂度模式

| 模式 | 适用情况 | 特点 |
| --- | --- | --- |
| light | 单页面、小作业、静态网页、无后端 | 文档少，推进快 |
| standard | 课程设计、小程序、后台管理、CRUD 项目 | 文档完整，适合大多数项目 |
| strict | 真实上线、多角色权限、敏感数据、频繁变更 | 门禁、日志、追踪更严格 |

如果不确定，建议先用 `standard`。

## 初始化项目文档

```bash
python software-dev-guide/scripts/init_project_docs.py \
  --project-path /path/to/project \
  --mode standard \
  --project-name "学生管理系统" \
  --project-type "Web 后台系统"
```

初始化后会在目标项目中创建 `docs/` 文档，例如：

```text
docs/00-项目状态总览.md
docs/01-项目需求说明书.md
docs/04-开发任务看板.md
docs/05-开发日志.md
docs/07-测试报告.md
docs/16-最终交付包说明.md
```

## 校验项目状态

```bash
python software-dev-guide/scripts/validate_harness_state.py \
  --project-path /path/to/project \
  --mode standard
```

它会检查：

- 是否缺少必要文档。
- 是否有未确认门禁。
- 是否有未解决异常。
- 是否有未验证回滚。
- 是否有模块锁残留。
- P0 需求是否缺少模块或测试用例。

## 查找下一步任务

```bash
python software-dev-guide/scripts/find_next_task.py \
  --project-path /path/to/project
```

它会根据文档状态判断下一步更适合：

- 询问用户确认。
- 调 A Agent 拆需求。
- 调 B Agent 开发。
- 调 C Agent 测试。
- 处理异常。
- 处理回滚。
- 准备最终交付包。

## Stitch 增强 UI

阶段 3 产品设计时，Skill 会让用户选择：

```text
1. Codex 原生 UI 设计
2. Stitch 增强 UI 设计
```

如果当前 Codex 环境已经接入 Stitch MCP，Agent 可以通过 Stitch 生成或读取页面设计。  
如果没有 Stitch MCP，则会降级为：

- Codex 原生 UI 设计。
- 用户上传 Stitch 截图。
- 用户提供导出文件或设计说明。

Stitch 是增强能力，不是必需能力。

## 注意事项

- Skill 的项目状态以目标项目的 `docs/` 文档为准，不依赖聊天记录。
- 开发前应先确认 MVP、技术方案和当前模块状态。
- 测试不通过时不要直接上线。
- 用户撤销需求或要求回退时，应记录到回滚与撤销文档。
- 如果文档、代码、测试状态不一致，应先进入异常处理流程。
